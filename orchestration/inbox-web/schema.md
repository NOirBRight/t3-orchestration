# Inbox question schema

The execution session saves the question as UTF-8 JSON and submits it with `node inbox.mjs ask <campaignId> <question.json>`. The command prints the question ID. Do not edit `inbox.json` directly.

```json
{
  "kind": "decide",
  "title": "Choose a release window",
  "ticket": "#42",
  "askerThreadId": "asking-session-threadId",
  "askerLabel": "#42 execution session",
  "blocking": true,
  "background": ["Validation is complete; this ticket is waiting for a release window."],
  "options": [
    {"key": "today", "label": "Today", "consequence": "Schedule the release today", "recommended": true},
    {"key": "tomorrow", "label": "Tomorrow", "consequence": "Schedule the release tomorrow"}
  ],
  "multi": false,
  "recommendation": "Today is recommended; everyone involved is online.",
  "media": [{"path": "media/preview.png", "caption": "Preview"}]
}
```

Required fields:

| Field | Type and meaning |
| --- | --- |
| `kind` | `decide` for a decision or `accept` for acceptance |
| `title` | Nonempty string stating what needs a decision or acceptance |
| `ticket` | Ticket number as a string or integer; a closing summary may use `Closeout summary` (fixed identifier; localize the title) |
| `askerThreadId` | Nonempty string identifying the original asking session that receives the answer |
| `askerLabel` | Nonempty string naming the asker on the page |
| `options` | Required for decisions, with at least one option; omit for acceptance |

Optional fields:

| Field | Type and default |
| --- | --- |
| `id` | Letters, digits, underscores, and hyphens only; unique within the Campaign; generated by the service if omitted |
| `blocking` | Boolean, default `false`. Set `true` only when the entire ticket has stopped |
| `background` | Array of strings, default empty array |
| `options[].key` | Nonempty string, unique among options |
| `options[].label` | Nonempty string |
| `options[].consequence` | String explaining the consequence; not displayed by default |
| `options[].recommended` | Boolean, default `false` |
| `multi` | Boolean, default `false`; whether a decision allows multiple choices |
| `recommendation` | String, default empty string |
| `media` | Array of media entries, default empty array |
| `media[].path` | Nonempty string identifying an existing readable file inside the Campaign directory; Campaign-relative paths are supported. Must not escape that directory or point outside it through a symlink |
| `media[].caption` | String; not displayed by default |

Acceptance questions use `kind: "accept"` and omit `options`. The page offers pass and rework; rework requires an explanation. Put images and videos in the Campaign directory before referencing them in `media`. Keep accepted media until the Campaign is archived.

The service fills in `createdAt`, `status`, `answer`, `history`, `times`, `forwardedTo`, `redo`, `notify`, `push`, `closedNote`, and `answeredBy`; do not supply them in the question file. An answer is `{choices: [optionKey], note: "comment", images: [uploadReference]}`. Acceptance answer choices are `pass` or `rework`.

Answer states are `open`, `saved`, `notified`, `read`, `forwarded`, and `closed`, in that order. Answers can be revised or withdrawn before the orchestrator handles them. Revising after forwarding marks `redo` and delivers the answer again. Closed questions are read-only; open a new question to reverse a closed decision. Comments are stored separately in `messages` and stop at `read`.

On validation failure, the command returns the field name and reason without adding the question to the Inbox. Fix invalid media paths before retrying as well.

Owner attribution is stored as `answeredBy: "owner"`; `"orchestrator"` identifies an orchestrator answer. Older owner attribution is normalized on read and written in the new form on the next normal update. Reading alone does not rewrite the Campaign file or discard its answer/history.

`push` records the latest new-question dispatch result: `{sent: boolean, at: ISO timestamp, endpoints: number}`. `endpoints` counts successful push-service responses, not devices that displayed a notification. Batched questions share the result. Missing means queued/not yet attempted (or a legacy item). No subscription data or endpoint addresses are stored here. A false result includes no remote entry, no subscriptions, or all sends failing; owner receipt confirmation remains separate.
